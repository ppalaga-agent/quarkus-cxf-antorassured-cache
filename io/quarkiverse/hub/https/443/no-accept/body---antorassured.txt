    <main><div><h1 id="welcome-to-the-quarkiverse-hub">Welcome to the Quarkiverse Hub!</h1>
<p>Quarkus is a Kubernetes Native Java stack tailored for the OpenJDK HotSpot and GraalVM, crafted from the best of breed Java libraries and standards, as well as an ever growing ecosystem of its extensions. At the beginning we were accepting all the contributed extensions in the core Quarkus repository. Eventually though it grew too large and lead to a maintenance overhead. In addition to that, in some cases it's simply not always sensible to include an extension into the main Quarkus repository. For example, an extension might want to have a release cadence which is independent of the core repository's lifecycle.</p>
<p>Quarkiverse is our solution to create a &quot;home&quot; for such extensions.</p>
<h1 id="what-is-quarkiverse">What is Quarkiverse</h1>
<p>The <a href="http://github.com/quarkiverse">Quarkiverse GitHub organization</a> provides repository hosting (including build, CI and release publishing setup) for Quarkus extension projects contributed by the community.</p>
<p>Quarkus extensions hosted in the Quarkiverse organization can easily be included into the Quarkus extensions catalog available on <a href="http://code.quarkus.io">code.quarkus.io</a>, <a href="http://extensions.quarkus.io">extensions.quarkus.io</a>, and the Quarkus command line tools (such as <code>mvn quarkus:list-extensions</code>, <code>gradle listExtensions</code>). To stay listed, the only requirement is that the extension keeps functioning, stays up-to-date and cause no harm.</p>
<h1 id="why-quarkiverse">Why Quarkiverse</h1>
<p>In the early days and actually up until recently, Quarkus extensions contributed by the community members (including the core Quarkus team) have been welcomed in the main Quarkus repository at <a href="https://github.com/quarkusio/quarkus">https://github.com/quarkusio/quarkus</a>. Today the main repository has grown a lot and it's evident that it simply becomes troublesome to work with it for its contributors. That and other maintenance and infrastructure related issues inspired the creation of a separate organization called Quarkiverse to host Quarkus extension projects contributed by the community (including the Quarkus core team members themselves).</p>
<p>The advantages of joining Quarkiverse are:</p>
<ul>
<li>Automated and secured publishing of your maven releases to Maven Central.</li>
<li>Automated Cross-testing of your extension with Quarkus builds/releases (see <a href="https://github.com/quarkusio/quarkus-ecosystem-ci">https://github.com/quarkusio/quarkus-ecosystem-ci</a>)</li>
<li>Consistent formatting and release of project</li>
<li>Quarkus team members can in an emergency (i.e. maintainers are missing) help and fix issues.</li>
</ul>
<p>Note: While the Quarkus project has the &quot;keys&quot; to publish under <code>io.quarkiverse</code>, each project in Quarkiverse is driven and maintained by
the lead of that project. They decide what happens with the project - Quarkiverse will just expect releases to be compatible with Quarkus - if a project
for some reason cannot do a release we can in the best scenario help or in the worst scenario we'll temporarily exclude the project from the affected registry entries to avoid end-users to have a bad experience.</p>
<p>If you do not want to commit to the above guidelines then you are more than welcome to publish an extension outside of Quarkus or Quarkiverse; and then you can
still be listed in the registry - it is just not handled automatically. In this case we request you to use your own group ID to clearly identify those artifacts are from a third-party organization.</p>
<h1 id="quarkiverse-and-quarkus-platform">Quarkiverse and Quarkus Platform</h1>
<p>The word Quarkiverse, derived from &quot;Quarkus&quot; and &quot;universe&quot;, is carrying the meaning of the universe of Quarkus extensions. In other words, it is intended to represent a part of the Quarkus ecosystem. However, at the same time, there is also a notion of a Quarkus platform. There is a significant difference between the two.</p>
<p>While the extensions under the Quarkiverse organization are generally independent projects lead by independent development teams, the fundamental promise of a Quarkus platform is any combination of the Quarkus extensions the platform consists of can be used in the same application without causing any conflict for each other. Quarkus platform implies coordination, cross testing and dependency version alignment across extensions that constitute the platform which is not generally applicable to the Quarkiverse extensions. It is, however, still possible for extensions hosted in the Quarkiverse to join a Quarkus platform assuming they satisfy the purpose and policies defined for that platform.</p>
<h1 id="joining-quarkiverse">Joining Quarkiverse</h1>
<h2 id="getting-an-extension-onboarded">Getting an extension onboarded:</h2>
<p>See <a href="checklistfornewprojects">ChecklistForNewProjects</a> for all the steps you'll need to start a new project in the Quarkiverse org.</p>
<p>The Quarkiverse team will provide the repository ready for development, nevertheless, it is always good to know that we respect the following conventions and policies.</p>
<h2 id="documenting-your-extension">Documenting your extension</h2>
<p>All Quarkiverse extensions can include documentation on <a href="http://docs.quarkiverse.io">http://docs.quarkiverse.io</a>.
See the <a href="documentingyourextension">documentation about the documentation</a> for details on how how to document your extension.</p>
<h2 id="managing-settings-on-the-github-repository">Managing settings on the GitHub repository</h2>
<p>Extension maintainers have full control over the repository settings, but be aware that the settings are infrastructure as code, managed with Terraform.
To change any setting in the repository (give push permissions to anyone, enable a GitHub app, etc.), update the repository's <code>.tf</code> file.
You may notice that, even as an extension maintainer, you have restricted permissions in the GitHub UI.
This is to reduce the risk of accidents where maintainers make changes which then get overwritten by the next Terraform run.</p>
<h2 id="expectations-for-quarkiverse-projects">Expectations for Quarkiverse projects</h2>
<p>Quarkiverse projects should follow some <a href="namingconventions">naming conventions</a> for maven coordinates and package names.</p>
<h3 id="identify-project-maintainer">Identify Project Maintainer</h3>
<p>Each project will have a GitHub team, and in here at least one must be listed and active as maintainer. This is the person that will be expected to lead and drive the project.</p>
<h3 id="provide-mechanism-to-do-cross-testing-of-named-quarkus-core-and-platform-versions">Provide mechanism to do cross-testing of named quarkus core and platform versions</h3>
<p>All Quarkiverse projects should have a build and test suite that can be parameterized to use specific Quarkus and Platform versions to ensure we can get
early warning of issues of master builds; but also to verify compatibility with maintenance branch/tags.
This is handled by the <a href="https://github.com/quarkusio/quarkus-ecosystem-ci">ecosystem CI</a>.</p>
<h3 id="parent-pom">Parent POM</h3>
<p>All Quarkiverse projects are expected to use <a href="https://github.com/quarkiverse/quarkiverse-parent">io.quarkiverse:quarkiverse-parent</a> as the parent POM.
This POM contains common project release and artifact publishing configuration.</p>
<h2 id="license">LICENSE</h2>
<p>The project is expected to be licensed under ASL 2.0.</p>
<h2 id="discussions">Discussions</h2>
<p><a href="https://docs.github.com/discussions">GitHub Discussions</a> are disabled by default in Quarkiverse extension repositories.</p>
<p>To avoid spreading information too much and make it hard to figure out where to post we have following default guidelines:</p>
<ul>
<li>Development questions should be addressed in the <a href="https://groups.google.com/g/quarkus-dev">Mailing List</a></li>
<li>User questions in <a href="https://stackoverflow.com/questions/tagged/quarkus">Stack Overflow</a> + the Quarkiverse project tag.</li>
</ul>
<p>However we can enable it in the repository if the extension maintainer really wants it (open an issue requesting that and ping the <code>@quarkiverse/quarkiverse-owners</code> team in the issue). However be aware that Core developers will not follow or be aware of these discussions unless explicitly mentioned.</p>
<h1 id="quarkus-extension-development-guides-and-references">Quarkus Extension Development Guides and References</h1>
<p>In case you need help creating a new Quarkus extension Maven project, please follow <a href="https://quarkus.io/guides/building-my-first-extension">Building My First Extension</a> guide.</p>
<p>Other useful articles related to Quarkus extension development can be found under the <a href="https://quarkus.io/guides/#writing-extensions">Writing Extensions</a> guide category on the <a href="http://quarkus.io">Quarkus.io</a> website.</p>
