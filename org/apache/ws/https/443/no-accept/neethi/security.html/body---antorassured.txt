<h1>Security and CVE Tracking</h1>
<p>This page tracks known vulnerabilities (CVEs) for Apache Neethi.</p>
<p>For reporting a new vulnerability, see <a class="externalLink" href="https://www.apache.org/security/">Apache Security Team</a>.</p></section><section><a id="Apache_Neethi_CVEs"></a>
<h1>Apache Neethi CVEs</h1>
<ul>
<li><a class="externalLink" href="https://www.cve.org/CVERecord?id=CVE-2026-91863">CVE-2026-91863</a>: Apache Neethi: Uncontrolled recursion while parsing crafted WS-Policy documents allows denial of service
<ul>
<li>Severity: Moderate</li>
<li>Affected versions:
<p>- Apache Neethi (org.apache.neethi:neethi) before 3.2.4</p></li>
<li>Description:
<p>A specially crafted WS-Policy document with deeply nested policy elements can bypass Neethi's nesting-depth limit and exhaust the thread stack, crashing the parser (denial of service). Users are recommended to upgrade to version 3.2.4, which fixes this issue.</p></li>
<li>Credit:
<p>This issue was found using Claude agents to study the security of open-source projects (finder)</p></li></ul></li>
<li><a class="externalLink" href="https://www.cve.org/CVERecord?id=CVE-2026-91864">CVE-2026-91864</a>: Apache Neethi: Crafted WS-Policy documents bypass element/attribute limits causing memory exhaustion
<ul>
<li>Severity: Moderate</li>
<li>Affected versions:
<p>- Apache Neethi (org.apache.neethi:neethi) before 3.2.4</p></li>
<li>Description:
<p>A specially crafted WS-Policy document can pack unlimited content inside a policy assertion, which Neethi copies into memory without counting it against its size limits, exhausting the heap (denial of service). Users are recommended to upgrade to version 3.2.4, which fixes this issue.</p></li>
<li>Credit:
<p>This issue was found using Claude agents to study the security of open-source projects (finder)</p></li></ul></li>
<li><a class="externalLink" href="https://www.cve.org/CVERecord?id=CVE-2026-91865">CVE-2026-91865</a>: Apache Neethi: Crafted policy references cause exponential expansion during normalization leading to denial of service
<ul>
<li>Severity: Moderate</li>
<li>Affected versions:
<p>- Apache Neethi (org.apache.neethi:neethi) before 3.2.4</p></li>
<li>Description:
<p>A small WS-Policy document using repeated policy references can force Neethi to re-expand the same references exponentially during normalization, consuming huge amounts of CPU and memory (denial of service). Users are recommended to upgrade to version 3.2.4, which fixes this issue.</p></li>
<li>Credit:
<p>This issue was found using Claude agents to study the security of open-source projects (finder)</p></li></ul></li>
<li><a class="externalLink" href="https://www.cve.org/CVERecord?id=CVE-2026-91866">CVE-2026-91866</a>: Apache Neethi: Crafted policies cause unbounded work during intersection leading to denial of service
<ul>
<li>Severity: Moderate</li>
<li>Affected versions:
<p>- Apache Neethi (org.apache.neethi:neethi) before 3.2.4</p></li>
<li>Description:
<p>A specially crafted pair of WS-Policy documents can force Neethi's policy-intersection to do exponential amounts of work, pinning the CPU for a long time (denial of service). Users are recommended to upgrade to version 3.2.4, which fixes this issue.</p></li>
<li>Credit:
<p>This issue was found using Claude agents to study the security of open-source projects (finder)</p></li></ul></li>
<li><a class="externalLink" href="https://www.cve.org/CVERecord?id=CVE-2026-91867">CVE-2026-91867</a>: Apache Neethi: Remote policy fetch lacks a total timeout, allowing a slow server to hang the request indefinitely
<ul>
<li>Severity: Moderate</li>
<li>Affected versions:
<p>- Apache Neethi (org.apache.neethi:neethi) before 3.2.4</p></li>
<li>Description:
<p>When Neethi fetches a remote policy reference, it only limits the time per read, not the whole transfer, so a server that trickles bytes slowly can keep the fetch alive indefinitely and tie up the calling thread (denial of service). Users are recommended to upgrade to version 3.2.4, which fixes this issue.</p></li>
<li>Credit:
<p>This issue was found using Claude agents to study the security of open-source projects (finder)</p></li></ul></li>
<li><a class="externalLink" href="https://www.cve.org/CVERecord?id=CVE-2026-66144">CVE-2026-66144</a>: Apache Neethi: Remote PolicyReference fetch lacks resource bounds
<ul>
<li>Severity: Low</li>
<li>Affected versions:
<p>- Apache Neethi (org.apache.neethi:neethi) before 3.2.3</p></li>
<li>Description:
<p>Although remote policy references are not retrieved during policy normalization, if they are manually retrieved via the API it can cause a denial of service attack if a huge policy is retrieved. Users are recommended to upgrade to version 3.2.3, which fixes this issue by imposing a default maximum size on data read from remote policy references.</p></li>
<li>Credit:
<p>Reported by LTSHFWJT (finder)</p></li></ul></li>
<li><a class="externalLink" href="https://www.cve.org/CVERecord?id=CVE-2026-66143">CVE-2026-66143</a>: Apache Neethi: Missing global alternative-output budget across policy computation paths
<ul>
<li>Severity: Moderate</li>
<li>Affected versions:
<p>- Apache Neethi (org.apache.neethi:neethi) before 3.2.3</p></li>
<li>Description:
<p>It is possible to bypass the maximum number of normalized policy alternatives that was introduced in Apache Neethi 3.2.2 via certain crafted policies, which may lead to a denial of service attack via resource consumption. Users are recommended to upgrade to version 3.2.3, which fixes this issue.</p></li>
<li>Credit:
<p>Reported by LTSHFWJT (finder)</p></li></ul></li>
<li><a class="externalLink" href="https://www.cve.org/CVERecord?id=CVE-2026-66142">CVE-2026-66142</a>: Apache Neethi: Uncontrolled recursion in policy processing
<ul>
<li>Severity: Moderate</li>
<li>Affected versions:
<p>- Apache Neethi (org.apache.neethi:neethi) before 3.2.3</p></li>
<li>Description:
<p>Apache Neethi is vulnerable to uncontrolled recursion when parsing policies that lack policy Ids or with deeply nested structures, which may lead to a denial of service attack when parsing policies due to runtime memory exhaustion. Users are recommended to upgrade to version 3.2.3, which fixes this issue.</p></li>
<li>Credit:
<p>Reported by LTSHFWJT (finder)</p></li></ul></li>
<li><a class="externalLink" href="https://www.cve.org/CVERecord?id=CVE-2026-42404">CVE-2026-42404</a>: Apache Neethi: Unrestricted HTTP Redirect Following in Policy References
<ul>
<li>Severity: Medium</li>
<li>Description:
<p>Apache Neethi does not impose restrictions on URIs when manually fetching remote policy references through the PolicyReference API. When an application explicitly calls this API to retrieve a policy from a remote URI, an outbound request may be made for arbitrary protocols and internal IP addresses.</p>
<p>From 3.2.2, only http or https URIs are allowed, and link-local, multicast, and any-local addresses are forbidden.</p></li>
<li>Recommendation:
<p>Users should upgrade to Apache Neethi 3.2.2 or later.</p></li></ul></li>
<li><a class="externalLink" href="https://www.cve.org/CVERecord?id=CVE-2026-42403">CVE-2026-42403</a>: Apache Neethi: Circular Policy Reference Infinite Loop 
<ul>
<li>Severity: High</li>
<li>Description:
<p>Apache Neethi does not properly detect circular references in policy definitions. When a WS-Policy document contains circular policy references (where Policy A references Policy B which references Policy A), the policy normalization process can enter an infinite loop or cause excessive recursion, leading to a stack overflow or application hang. An attacker can craft malicious policy documents with circular references to cause a Denial of Service condition</p></li>
<li>Recommendation:
<p>Users should upgrade to Apache Neethi 3.2.2 or later.</p></li></ul></li>
<li><a class="externalLink" href="https://www.cve.org/CVERecord?id=CVE-2026-42402">CVE-2026-42402</a>: Apache Neethi: Policy Normalization Unbounded Resource Allocation DoS 
<ul>
<li>Severity: High</li>
<li>Description:
<p>Apache Neethi is vulnerable to a Denial of Service attack through algorithmic complexity in policy normalization. Specially crafted WS-Policy documents can trigger an exponential Cartesian cross-product expansion during the normalization process, causing unbounded memory allocation that exhausts the JVM heap. This occurs when the normalization process generates an excessive number of policy alternatives without bounds, leading to runtime memory exhaustion.</p></li>
<li>Recommendation:
<p>Users should upgrade to 3.2.2 which limits the maximum number of normalized policy alternatives.</p></li></ul></li></ul></section>        </main>
